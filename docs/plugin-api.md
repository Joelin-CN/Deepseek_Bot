# 插件系统与原生 API

## 分层

- `src/companion/api`：原生插件使用的公共接口。
- `src/companion/plugin_system`：插件宿主与生命周期管理。
- `src/companion/core/tools`：模型工具的统一登记和执行。
- `src/companion/compat/astrbot`：AstrBot 插件语义适配。
- `src/astrbot`：已支持的兼容导入入口。

当前没有加载器、插件 SDK 或实际插件实现。

## 插件宿主的目标能力

1. 识别插件信息、版本、入口、API 要求和依赖。
2. 区分原生插件与 AstrBot 兼容插件，选择对应加载方式。
3. 初始化、启用、停用和卸载插件。
4. 注册及撤销命令、事件处理、工具和配置。
5. 管理插件拥有的后台任务、资源、日志和数据空间。
6. 报告加载错误、依赖冲突和不支持的接口。

工具只是插件可提供的一类能力，插件系统也可以承载事件处理和其他扩展。

## 原生接口边界

原生插件使用框架定义的消息、执行上下文和结果格式。公共能力的候选范围包括消息、会话、模型、工具、记忆、插件存储和任务管理；具体签名在实现前确定，不在当前阶段创建伪 SDK。

## 生命周期与资源归属

宿主需要知道每个事件处理器、工具和后台任务由哪个插件注册。插件停用或卸载后，宿主应撤销注册并清理对应资源，避免出现“插件已停用，任务仍在执行”。

## 代码和数据位置

- 根目录 `plugins/`：随项目维护的内置插件源码。
- `examples/plugins/`：后续原生插件开发示例。
- 外部安装插件：放在独立运行数据目录，避免混入本项目源码。
- 插件状态和文件：使用各自数据空间，真实数据不提交到 Git。

## 信任模型

初期只加载可信的本机 Python 插件。同进程权限声明和命名空间属于管理约定，不构成安全隔离。

若后续需要运行不可信插件，应另行设计进程隔离和调用边界，并重新评估 AstrBot 兼容范围。
