# AstrBot 插件兼容范围

## 当前状态

目标是尽量复用 AstrBot 插件生态，但当前没有兼容实现，也没有验证过任何真实插件。目录或文档不能视为兼容承诺。

尚未确定具体 AstrBot 基线版本或提交；应结合首批目标插件选择并固定基线。

## 实现边界

`src/astrbot` 承接受支持的导入路径，转换逻辑集中在 `src/companion/compat/astrbot`，再调用原生 API。自有内核不依赖 AstrBot 的内部类型。

实现环境中避免同时安装真实 AstrBot 包，以免与本项目的兼容命名空间冲突。

## 计划覆盖顺序

| 范围 | 当前状态 | 后续需要验证 |
| --- | --- | --- |
| 入口和元数据 | 未实现 | 发现、加载、版本和依赖检查 |
| 事件与命令 | 未实现 | 过滤器、参数、优先级及返回行为 |
| Context 与消息 | 未实现 | 身份、会话、发送及异步行为 |
| 配置与存储 | 未实现 | 配置类型、插件数据范围和持久化 |
| 模型与工具 | 未实现 | 工具登记、调用循环、结果和异常 |
| 私有核心接口或特定平台能力 | 不预先承诺 | 按目标插件需求单独评估 |

导入成功不等于插件可用。每项兼容能力都需要检查接口签名、返回结构、异步执行和错误行为；不支持时明确报告。

## 验证样本

首批目标插件尚未由用户选择。后续以真实名称、来源仓库和固定版本建立记录，并覆盖命令、工具调用及插件存储等代表性路径。

`tests/plugin_compatibility` 用于保存兼容检查，`tests/fixtures` 默认只放合成或脱敏样本。实际插件代码引用与许可记录另行登记。
