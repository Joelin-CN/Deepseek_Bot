# 记忆服务与持久化

## 边界

`memory` 是框架服务，负责记忆的新增、检索、更新、删除、来源与范围管理；`persistence` 负责数据库连接、存储实现和迁移。

当前只确定结构，不确定具体记忆提取、人设或自主活动策略，也不创建实际数据库。

## 数据分类

| 数据 | 负责模块 |
| --- | --- |
| 原始消息和会话历史 | 会话服务与持久化层 |
| 长期记忆及其来源、修订记录 | 记忆服务与持久化层 |
| 文本及向量检索索引 | 可替换的检索实现 |
| 插件配置、状态和资源记录 | 插件宿主与插件存储接口 |
| 导入文档和知识库内容 | 后续独立确定，不直接等同于记忆 |

## 服务需要覆盖的能力

- 创建、查询、修改、删除记忆记录。
- 保存记录来源、范围、创建时间和修订关系。
- 在检索进入模型上下文之前检查可见范围。
- 提供可更换的文本检索及向量检索实现。
- 向原生插件和兼容层提供统一服务入口。

权限和可见范围检查由服务执行，不能只写在提示词里。私聊、各个群和可公开经历的具体使用策略另行讨论。

## 初始存储方向

SQLite 作为初期正式记录存储的候选方案。不同业务数据可以采用不同表和迁移记录，不要求一开始拆成多套数据库服务。

向量索引视为可重建的检索数据，记录对应嵌入模型、版本和维度。具体后端与嵌入服务尚未选择，不默认聊天 API 同时提供嵌入能力。

数据库迁移位置为 `src/companion/persistence/migrations`。真实数据库与索引放在独立运行数据目录，不提交到 Git。

## 插件关系

框架提供记忆基础服务；记忆工具、提取或整理策略可以通过插件扩展。`plugins/memory_tools` 是预留的内置插件位置，目前没有可调用工具。

兼容插件存储接口和框架记忆接口是不同用途，不能把插件 KV 存储自动解释成长久记忆。
