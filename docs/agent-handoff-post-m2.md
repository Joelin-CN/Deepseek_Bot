## 四、M3：通用会话、持久化和基础记忆

### M3A：把私聊链路扩展成可承载后续模块的内核

现有代码的会话锁和短期历史按 user_id 管理。接入群聊前，建立统一会话标识，至少区分平台、机器人账号、私聊／群聊、会话目标；群内发送者单独记录。上下文、并发锁、任务、消息去重和记忆范围都使用一致的标识规则。

实现明确的运行上下文：发起者身份、来源会话、任务标识、允许能力和取消信号。身份和权限取自已验证的消息来源及本地配置，不接受模型参数或聊天文字自行声明“我是主人”。会话隔离和身份授权分别处理。

先复查并修正会影响后续扩展的现有问题：
- OneBot 每次重连都重新确认机器人身份，通过后再处理该连接的业务消息。
- 动作区分确认成功、明确失败和结果未知。消息发出但回执丢失时，不承诺恰好一次，不盲目重发。
- 失效连接中尚未发送的旧动作不能在重连后意外发送；覆盖“已入队但超时／取消”和“服务端已执行但回执前断线”的测试。
- 事件队列、待处理任务和模型并发有上限；单条异常不破坏接收循环，不能靠无限创建任务承受群消息。
- 历史消息除了条数，还限制总输入长度／估算 token 和输出长度；裁剪不能破坏工具调用与结果的配对。
- 模型已生成、QQ 已送达、发送失败或未知应能区分，避免把未送达内容直接当成已完成对话。

持久化初期使用 SQLite，先调查本机能力并设计迁移。通用连接、事务和迁移在 persistence；业务规则留在会话、记忆等服务。处理异步调用时的阻塞、并发写入、异常关闭和恢复，不为此引入多套数据库服务。

数据库、插件数据、任务产物放在明确配置且被 Git 忽略的位置，不能依赖启动时的工作目录，也不把本机绝对路径写死在业务代码中。为会话记录、消息状态、插件 KV、记忆、任务和用量定义实际所需的数据结构；不预建一批无人使用的空表。

验收：原有 M1/M2 回归通过；不同私聊与群会话不串线；断线与取消不会让旧回复延后误发；迁移、重启恢复和并发访问通过测试。

### M3B：基础长期记忆服务

区分原始消息、短期上下文、长期记忆、插件 KV、浏览经历，不把保存聊天历史当作完成记忆服务。

先实现可用的最小能力：
- 新增、查询、修改、删除和分页查看。
- 来源消息／任务、时间、范围、修订关系和必要的状态。
- 显式记忆：我可以要求“记住／查看／修改／忘记”一条信息；第一版不自动提取所有聊天内容。
- 按会话恢复有界历史，按权限检索相关记忆后再进入模型上下文。
- 中文检索有实际样例；若采用 SQLite FTS，验证当前构建和中文匹配效果，不假定默认分词一定适用。
- 删除或撤销后，在线检索、上下文缓存和派生摘要不能继续当作有效记忆；说明原始消息和备份的保留规则。

默认范围：我的私聊记忆只用于对应私聊；每个群的记录和记忆分别隔离。可公开的机器人经历通过显式发布范围使用，不能把私聊或群聊内容自动变成公共经历。可见性在查询和组装上下文前由服务检查，不能只靠提示词。

自动摘要、记忆提取和向量检索留有扩展点，但没有选定嵌入服务前，不默认 DeepSeek 聊天接口提供 embedding，也不为“预留”安装向量数据库。

验收：私聊要求记住的信息重启后仍可检索，忘记后不再被检索使用；跨范围检索被拒绝；迁移、修订、删除、中文检索和上下文上限有测试。

原生 API 在 src/companion/api；插件宿主在 plugin_system。工具注册是插件的一项能力，不能代替插件宿主。

第一版实现：

- 加载、初始化、启用、停用、卸载及加载失败报告。
- 命令、事件处理器、工具和后台任务的注册与撤销。
- 插件独立的数据空间、KV 存储、日志与资源归属。
- 一个插件失败时的明确隔离处理，避免拖垮正常聊天。
- 处理器顺序、命令消费／继续传播、异常行为有明确语义。
- 停用后撤销其注册、取消其任务、清理其资源；正在执行的调用如何结束要有测试。

根目录 plugins 存本项目维护的内置插件；运行时安装的外部插件放在独立数据目录。先提供一个可运行的最小原生示例，并把记忆命令等适合的能力接成内置插件，避免 SDK 只存在于文档里。

不做插件市场、任意代码在线安装或复杂热更新。第三方依赖冲突要明确报告，不自动升级整套环境来迁就插件。

验收：加载插件后命令可用，停用后命令和后台任务停止；重启后按配置恢复；错误插件有清楚的错误记录；核心不依赖插件的私有实现。

## 六、M5：统一工具循环与 ego-lite 网页任务

### M5A：工具调用内核

先实现统一工具描述、参数校验、执行、超时、取消和结构化结果。工具归属插件，但权限、预算和执行上限由宿主统一检查。

扩展现有 DeepSeek 适配器，使其保留和处理模型真实的 tool_calls，而不是只读取 content。按当前官方协议完成“模型请求工具 → 校验权限和参数 → 执行 → 带对应 tool_call_id 返回结果 → 模型继续生成”的循环。

第一版可以继续使用现有非流式、关闭思考模式的路径，不为工具调用另换整套模型 SDK。核对当前工具协议和所选模型能力，不依赖旧教程。

限制每轮工具调用数、模型轮数、总耗时、工具结果长度和并发；未知工具、非法参数、重复调用、工具失败、用户取消及达到上限都要有明确结果。取消要传递到浏览器任务或子进程，不能只停止等待。

任务的能力和数据范围贯穿模型、工具、插件与子任务，不能因后台执行或兼容层调用而扩大。具有外部副作用的动作不能在结果未知时自动重试。

先用无外部副作用的测试工具跑通完整闭环，再接浏览器。

### M5B：ego-lite 适配与真实网页任务

先读取本机 ego-browser skill，验证当前 CLI、浏览器连接和 TaskSpace 生命周期，再实现 adapters/ego。复用本机 ego-lite，不默认换成 Playwright、Selenium 或别的浏览器。

架构可采用固定的本地 Node 桥接程序或当前 ego 正式支持的接口，由 Python 通过结构化消息调用。具体方式根据当前文档选择，不把任意模型生成的 JavaScript、PowerShell 或 shell 交给主机执行。

模型看到的是受控的搜索、打开页面、读取、根据页面观察操作、结束任务等能力。浏览器适配层内部必要的脚本与通用主机执行工具分开，不向模型开放任意文件读取、环境变量、Cookie 或任意代码执行。

第一版支持公开网页的信息查找、阅读和归纳；返回标题、实际来源链接和结果。搜索引擎或站点能力要实际验证，不默认已有另一个收费搜索服务。

- 每个真实网页任务使用独立的任务状态和明确的 TaskSpace 归属；同一目标分轮继续操作时复用自己的空间，不为恢复失败反复新建空间。
- 控制标签页、导航次数、读取长度、超时和任务并发；只清理自己创建的资源。
- 不假定 TaskSpace 等于独立浏览器 Profile 或登录态隔离，不擅自选择、切换或清空我的 Profile。
- 后台自主浏览和群成员任务第一版仅限公开页面。已登录网站、私人页面和本地网络资源没有自动授权；若现有浏览器接入无法可靠限制，就明确禁用对应来源的浏览能力，先解决边界。
- 页面、搜索结果、插件输出都是外部数据；不能据此修改权限、执行管理员命令、泄露私聊或自行安装程序。
- 发帖、评论、私信、上传、购买、账号修改等操作不属于默认公开浏览权限。以后扩展时单独按动作范围授权。

验收：我在 QQ 私聊里让她查找一件公开信息，她实际通过 ego-lite 浏览、返回有来源的结果；取消和超时可用，浏览任务结束后资源正确清理；日常自动化测试不访问真实网站。

参考当前 [DeepSeek Tool Calls 文档](https://api-docs.deepseek.com/guides/tool_calls) 和本机 ego-browser skill。不要将网页内容插入为系统指令。

## 七、M6：批准群的应答与群发现建议

先向我确认一个可用于联调的群及其范围，再启用真实群消息处理。未确认前完成合成群事件和替身服务测试，不向任意现有群发送测试消息。

第一版群能力：
- 群事件标准化、群白名单和按群独立的上下文／记忆／限额。
- 区分私聊发送、群发送、真实 @、引用与普通正文；正文写“@机器人”不自动等同平台 @。
- 起步采用白名单群内被 @ 或明确命令时回复；自然参与和主动发言在 M8 配置后启用。
- 群内普通成员不是框架管理员，QQ 群管理员也不自动获得框架管理权限。
- 群成员能否调用网页工具尚未决定，默认关闭该入口，向我确认后按群／角色配置。
- 命令和工具仍走统一权限、任务和发送服务，不能由插件另开绕过路径。
- 处理群消息洪峰、消息长度、冷却、机器人互相应答及重复事件；不让每条群消息都无条件触发一次模型调用。
- 群、私聊和不同群之间不能互相带出私人上下文。

群发现只根据可访问的公开资料生成建议，附来源和不确定性。先核实 SnowLuma 实际支持的能力；不要编造通用的“搜群／入群 API”。找不到可靠线索就如实说明。

入群必须由我针对具体群作决定。可以先由我手动加入；如后续使用实际支持的申请／邀请接口，批准也必须绑定具体群和动作，网页或群成员不能代替我批准。不自动加群、自动同意所有邀请或自动添加好友。

验收：批准测试群的 @ 应答正常；非白名单群不触发；不同群不串上下文；群成员不能调用主人管理命令；真实发送结果与 QQ 客户端观察相符。

## 八、M7：AstrBot 插件兼容层

这项工作要实际交付一个明确范围的兼容版本，不只做同名空函数。

先调研当前 AstrBot 源码和插件生态，选择并固定 AstrBot 版本／提交以及首批目标插件。没有指定插件时，给我 2–3 个来源明确、依赖较少的候选，再确认实际安装名单；等待时可以先用官方最小实例和合成契约用例开发兼容接口。

- 核心继续使用 companion 自有类型。
- src/astrbot 只提供已支持的导入入口。
- src/companion/compat/astrbot 负责语义映射，再调用原生服务。
- 不安装真实 AstrBot 包来掩盖兼容缺口，也不把 AstrBot 主程序整体搬进来。
- 按目标插件需要覆盖 Star／Context、事件与命令过滤、消息结果、异步处理、配置、存储、模型和工具接口；每项以固定上游版本为准。
- 覆盖返回值与异步生成器、过滤顺序、停止传播、异常、初始化和 terminate 等实际行为。导入成功不能算兼容成功。
- 不支持的接口明确报错并指向兼容清单，不以静默空结果冒充实现。
- 兼容插件调用模型、浏览器、记忆或发消息时仍遵循统一权限、预算和来源范围。
- 同时记录原生 API 版本、兼容基线、已测插件来源／版本／依赖和通过范围。

目标是至少跑通一款我确认的真实 AstrBot 插件，并用契约测试覆盖命令、工具和插件存储等代表路径；没有验证的插件不写成“全部兼容”。

参考 [AstrBot 最小插件实例](https://docs.astrbot.app/dev/star/guides/simple.html) 及实际固定版本源码。复制具体代码、引入测试插件前核对各自许可并更新 docs/upstream-sources.md。项目发布许可仍未选定，不自行添加默认许可证。

## 九、M8：可控自主活动与自然参与

完成前面的任务、权限、预算和浏览器能力后，再实现自主活动。自主活动应走同一套任务执行器、工具入口和用量记录，不另写一个绕开权限的后台脚本。

先实现机制：
- 定时或事件触发、可配置活动时间、最小间隔和全局并发。
- 可见的任务状态：等待、运行、取消、超时、失败、完成；人工批准状态与发送结果另行记录。
- 兴趣／公开来源范围、单次最大步骤／耗时／成本、每日和每月额度。
- 用户主动任务优先；任务可取消、可暂停，重启后默认不重放结果未知的外部动作。
- 定时触发可以由本地规则决定，不为每分钟“想一想要不要活动”调用一次模型。
- 浏览所得形成带来源、范围和时间的经历记录，不自动将外部内容当作已确认事实或公共长期记忆。
- 区分“去浏览”与“把发现发给人／群”；推送对象、频率和条件单独受配置限制。
- 自主发言和入群建议也受冷却、群范围和权限限制。

启用前再向我确认尚未决定的参数：感兴趣的话题／站点、活动时间和频率、月预算硬上限与自主活动份额、哪些群允许自然参与以及何时可以主动私聊我。可以逐项问，不要一开始抛出整套人格问卷。

在我确认前，可以完成配置、调度器、模拟时钟测试和手动触发的公开浏览演示；定时自主浏览、主动群发言和主动推送保持未启用。不要把“配置待确认”写成真实自主活动已验收。

人格先提供一个集中、可版本化的配置入口，沿用现有简洁中文应答即可。具体性格、经历、记忆提取和发言策略以后和我讨论；“有活人感”不靠伪造已完成的行动或经历实现。

验收：获准的一次自主公开浏览能按规则运行、记录来源并正确结束；暂停后不再新建自主任务，运行中任务可取消；超预算、超时、重启及禁止范围的情况均有测试。没有我的启用参数时，明确保留这一项为待验收。

## 十、M9：长期运行、用量和最小管理能力

管理入口先采用主人私聊命令和本地命令行，不默认开发大型 Web 面板。命令覆盖状态、插件列表与启停、任务查看与取消、自主活动暂停／恢复、记忆管理、用量查看；具体命名避免与插件命令冲突。

- 主人身份与管理员授权来自本地配置；不能由昵称、群头衔或模型猜测。
- 模型全部调用路径统一计量，包括插件、摘要、后台活动和失败后重试；分清原始 token、按价格表估算的费用与服务商实际账单。
- 价格表记录模型、币种、来源和生效日期；不要硬编码一份永久有效的价格。
- 使用本地硬阈值、并发预留和每次请求上限控制消耗；单纯事后累计 usage 不能作为严格的消费保护。未知价格或未知消耗不能悄悄按零计算。
- 给主人对话保留可配置额度，自主活动优先降级；总额度耗尽时仍可用本地状态／暂停命令。
- 日志脱敏、滚动和保留期限；默认不记录完整私聊、网页正文、工具密钥或鉴权头。
- 数据库备份、恢复演练、迁移失败恢复和运行目录说明。
- 单实例保护、健康状态、异常任务回收、优雅退出、重连退避，浏览器不可用时仍能普通聊天。
- Windows 启停脚本核验进程身份和创建信息，不能仅凭可能复用的 PID 杀进程，更不能批量结束 QQ 或浏览器。
- 明确睡眠、锁屏、断网、QQ 掉线及人工登录对在线状态的影响，不承诺 Windows 电脑一定全天在线。
- 开机启动／计划任务等持久系统配置先准备可审查方案，在我选择启用后再设置。若需本地管理 HTTP 接口，仅回环监听并鉴权；界面范围另行确认。

验收：可按文档从干净启动流程恢复运行，能查状态与用量，停止自主任务有效，备份能恢复；普通聊天、浏览器故障、插件故障、断网恢复不会相互拖垮。记录实际观察时长，不以短测试宣称长期稳定。
